Section 01
三機艦隊 節點總覽
M4 Hub 負責協調與輕量任務；M5 Max 承接重量級 ML 推理；Windows Beaver 處理 Playwright 爬蟲與 CUDA 轉錄。三台各司其職，互補不重疊。
HUB M4
Apple M4 · 16GB · 無 MLX
角色：Hub 協調 / Kai backend (FastAPI :5002) / NexPilot PWA / NexDesk hub / 輕量任務
本地模型：
Ollama qwen2.5:3b · gemma4:e4b（Logger 用）
連線：本地 / Tailscale M4·內網
⚠ 雷區
只 16GB，常吃緊（剩幾百 MB）→ 勿派重爬蟲 / 大模型
MAX M5
Apple M5 Max · 128GB · MLX v0.31 已裝
角色：重量級 ML 推理 / 本地 LLM 主力 / 重爬蟲 / NexPilot 遠端螢幕被控端
本地模型：
MLX server (:8771) + Ollama (:11434)，詳見模型矩陣
連線：ssh «用戶»@M5·內網（Tailscale）
⚠ 雷區
MLX 大模型(gpt-oss-120b 59GB)會吃 100GB+，看實際剩餘不是看總量
BEAVER Windows
Ryzen 7 + RTX 3050 (4GB CUDA) · 16GB
角色：Playwright 爬蟲 / review 爬蟲 / faster-whisper 轉錄 worker / CUDA / Windows 測試
本地模型：
faster-whisper (cuda float16)；LLM 走雲端
連線：beaver skill / WinRM / Win·內網:8100
⚠ 雷區
爬蟲 --workers 2（4 個 Firefox 把 16GB 撐爆）；beaver put >5MB 截斷 → 改 HTTP over Tailscale
派工鐵則
鐵則 01
派工前一律先跑 fleet CLI 看三台 RAM / load / 熱節流，別憑印象
鐵則 02
任一台 RAM 剩 <2GB 或 🔥熱節流 → 別再加，挪去剩最多的那台
鐵則 03
三台都別閒：大量平行工作（爬蟲 / 發現 / 萃取）攤到 M4 + M5 + Win
鐵則 04
長跑任務用 nohup（Mac）/ Start-Process Hidden（Win）detach + 背景 watcher

勞力 Tier 1 Tier 0 搞不定但量大 Haiku / Sonnet pipeline 中

決策樹：要派一個寫 code 的活，怎麼選？
❓ 能用 nim-write / M5 本地 coder / NIM 搞定嗎？

走 nim-write 或 ssh M5 qwen3-coder
零成本，盡量用這條
❌ NO → 需要 Claude 級推理？
YES → Sonnet subagent（Tier 2）
NO → 拆小工作再回到 Tier 0
⛔ Codex 凍結（2026-06-12）
原本「先 codex exec」一律改走 nim-write / M5 / NIM。Opus 永不直接寫 production code（Tiny ≤30 行 / 1 檔例外）。
口訣
能 Tier 0 不上 1，能 1 不上 2，永不 Tier 3。能不用 Agent tool 就不用。

角色邊界（不重疊）
Quill — 程式碼層
PR / diff · 規格合規 · DRY · 測試缺口。不做架構簽核。
Forge — CI Gate
lint / test / build / deploy + Evidence Gate + Critical 部署後 1hr Runtime Watch。
Ray — 設計層
任務定義 · 架構風險 · 開工簽核 · veto。不做日常 code review。
Sentinel — 密鑰掃描
auth · payment · email · 登入態瀏覽器自動化 · 外部 API / token / secrets 任一觸發即強制列入。
Security Review Required 條件
auth · payment · email 收發 · 登入態瀏覽器自動化 · 外部 API / token / secrets。觸發但無 Sentinel 結果 → Critical 不得交付。
